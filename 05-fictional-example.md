# Choose a first step before proposing a large project

**Entirely fictional teaching example.** The people, source notes, numbers and review below are invented to show how to use the files. This is not a client case, an observed user test or evidence of commercial results.

## The situation

An independent consultant speaks with a small design studio. The owner wants “more order in our enquiries.” The consultant considers a new CRM, a reporting redesign or a small review of recent enquiries.

## The map, written before acting

| Field | Fictional entry |
|---|---|
| Recipient | The studio owner, choosing the first stage of work |
| Question | What should we examine first to find out where enquiries are lost? |
| Observations and sources | Imagined meeting note, 13 September: the owner says enquiries arrive through email and a website form. Imagined sample sheet, same date: some rows have no first-response time or outcome. |
| What this supports | The selected records have missing fields. It does not establish the number of lost enquiries or their cause. |
| Unknown | How complete the source records are; where replies slow down; whether the current CRM contributes |
| Assumption | Some of the problem may come from enquiry handling rather than the tool itself. |
| Option A | Replace the CRM now. Larger commitment; the cause remains uncertain. |
| Option B | Reconstruct ten recent enquiries. Smaller scope; may reveal missing information. |
| Option C | Postpone the review until access to the source records is agreed. |
| Decision | Ask the owner to approve option B and provide access. |
| Action, owner and deadline | The consultant sends the scoped proposal by 14 September. Proceed with the review only if access is agreed. |
| Completion criterion | A proposal is sent; if the review proceeds, each selected enquiry has a source, first-response time, next step and outcome, or an explicit “unknown”. |
| Effect to observe | Can the owner use the table to choose a justified next step? This is separate from filling in the table. |
| Review date | 20 September |
| What could change the choice | If the records cannot be reconstructed, improve collection first. If delays are not found, consider a different explanation. |

## A usable proposal

“I suggest starting with ten recent enquiries. We can reconstruct their path and identify where information or actions are missing. First, let's agree which records to use and who can provide access. In a week, we can review the table and decide what to investigate next.”

## An imagined review, written as a separate later entry

**The following outcome is also invented. In real work, leave the review blank until you have observations.**

- **Date:** 20 September.
- **Action:** The consultant sent the proposal. In this imagined scenario, the owner agreed and supplied records.
- **Result:** Ten enquiries were listed. Six had a recorded first-response time; four remained unknown. Each row retained its source reference.
- **Use:** The owner used the table to choose a one-week trial of recording first-response times.
- **What remains unknown:** The sample does not establish lost revenue, the rate of lost enquiries or whether a new CRM would help.
- **Next decision:** Keep the current CRM for now; test whether the missing fields can be collected consistently.
- **Next action and review:** Agree who records the fields, then review the next week's entries on 27 September.

The map did not prove that a CRM replacement was unnecessary. It showed how to choose a smaller check before making a larger commitment.
